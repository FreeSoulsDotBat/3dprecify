# Contrato de API — 019 (PR-D e PR-E)

Só duas fatias tocam a API. Tudo aqui é **aditivo**; o drift-guard (OpenAPI + Orval) congela o
resultado e a regeneração precisa ser **idempotente** (regen duas vezes ⇒ diff vazio). `ProductOut`
continua **sem campo de dinheiro derivado de cálculo** — o drift-guard é a prova.

Autoridade: [ADR-0033](../../docs/adr/0033-observacao-e-fixacao-de-preco.md), [ADR-0034](../../docs/adr/0034-orcamento-montado-motor-e-congelamento.md). Wire em camelCase (alias_generator); erros pelo `ErrorCode` enum.

---

## PR-D — `price-observations` (NOVO recurso, separado do produto)

```
GET  /api/v1/price-observations
     → 200 { items: [{ subjectKind: "PRODUCT"|"KIT", subjectId, observedPrice, observedAt,
                       modelVersion, catalogVersion? }] }
     · entitlement: require_catalog_read (aceita lapsed; recusa none → 403 ENTITLEMENT_REQUIRED)
     · só as observações da conta (owner_uid do token)

PUT  /api/v1/price-observations
     body { items: [{ subjectKind, subjectId, observedPrice, modelVersion, catalogVersion? }] }  // ≤ 500 itens; (kind,id) único no lote ⇒ senão 422
     // `observedAt` NÃO vem do corpo: o servidor carimba `now()` (auditoria 27/08 — precedente `device_*`: o que
     // o servidor não verifica leva prefixo; aqui ele verifica). Schemas com `extra="forbid"`; `ownerUid` no corpo ⇒ 422.
     → 200 { upserted: n }
     · entitlement: require_entitlement (exige active) — lapsed NÃO escreve
     · idempotente por (subjectKind, subjectId): upsert na linha única da conta
     · o servidor VALIDA (money ≥ 0, não NaN; kinds; ids uuid) e GUARDA — nunca recomputa, compara ou conta
     · chamado pelo cliente DEPOIS do render bem-sucedido, em lote, uma vez por visita
```

**Não existe** `DELETE` (a linha é sobrescrita) nem observação por item (`/{id}`): o lote é a unidade.

## PR-D — `products` (campo aditivo)

```
PATCH /api/v1/products/{id}   body { sellerFixedPrice: money | null }   // ROTA NOVA (products.py só tem GET/POST/PUT/DELETE) —
                              // corpo com UM campo, `extra="forbid"`, porta `require_entitlement`; `sellerFixedAt` carimbado pelo servidor
GET   /api/v1/products         → ProductOut + { sellerFixedPrice: money | null, sellerFixedAt: datetime | null }
```

- `null` = acompanhando o custo (desfixar). `>= 0`, não NaN.
- **Nunca** um `price` calculado; `sellerFixedPrice` é declaração do vendedor (o nome é a guarda).
- Não participa de `boms`, `snapshots` nem `scenarios` (não participa de `boms`/`snapshots`/`scenarios` — provado por AUSÊNCIA de campo em `BomLineOut`/`BomOut`, não por comportamento: o servidor nunca calcula).

## PR-D — nome único (regra transversal em `filaments`/`printers`/`products`/`boms`)

```
POST/PUT ... { name }  →  o servidor grava name (≤120, pydantic) + name_norm = left(norm, 200) (NFD → sem Mn → lower → trim → colapsar)
   conflito em (owner_uid, name_norm) entre vivos  ⇒  grava com sufixo "(2)", "(3)"… e devolve o
   registro com o nome FINAL (200/201) — sem erro, sem aviso (Q5)
```

- A recusa "Este nome já está no catálogo" é do **formulário** (cliente), antes de enviar.
- Corrida (duas criações simultâneas do mesmo nome normalizado) ⇒ uma renomeada, nenhuma perdida — teste
  de concorrência no backend.
- Vetor de normalização compartilhado (fixture única lida por pytest e vitest).

## PR-E — `snapshots` (CHECK aditivo — não há enum Postgres no schema; `kind`/`headline_basis` são TEXT + CHECK)

```
POST /api/v1/history   body { kind: "SINGLE"|"KIT"|"QUOTE", headlineBasis: ...|"PRECO_ORCAMENTO",
                              headlineTotal, payload: { kind:"QUOTE", lines[], totals.precoOrcamento,
                              discount{mode,value,amount,grossTotal}, costFloor, modelVersion:"4.2.0", schemaVersion:1 }, ... }
   // dinheiro (incl. discount.value) como STRING decimal; quoteValidityDays NÃO vai no payload (é coluna)
```

- `headlineTotal` **==** `payload.totals.precoOrcamento` — amarrado pelo `CHECK` do banco (o `CASE` ganha
  o ramo `PRECO_ORCAMENTO` na migração 0009; teste insere divergente e **espera 4xx/recusa**).
- `_BASIS_TOTAL_KEY` e os `Literal` de `SnapshotIn` crescem juntos; guarda: conjunto do Literal ==
  conjunto de chaves do dict (sem ela, enum novo vira 500 que o outbox re-tenta para sempre).
- Imutabilidade, `UNIQUE (owner_uid, client_snapshot_id)` e `PATCH` só-de-`label`: **intactos**.
- Export (`GET /api/v1/history/{id}/quote.pdf` e `GET /api/v1/history/export.csv` — os endpoints REAIS,
  `export.py:78-84,:38-42`; o caminho `/export?format=` deste contrato estava errado): o PDF ganha as linhas bruto → desconto →
  total **só quando** `payload.discount` existe; rodapé não-fiscal mantido; geometria com nome longo.
